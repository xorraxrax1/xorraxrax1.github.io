Rubrik Cross-Account Pairing — OAuth authorization-code leak PoC

Finding: the authorization popup sends {code,state,fqdn} via window.opener.postMessage(payload, "https://" + serviceConsumerOrgUrl), where serviceConsumerOrgUrl comes straight from the URL query string with no allowlist. Because the attacker page is the opener AND chooses that value, the browser delivers the OAuth code to the attacker.

Preconditions to reproduce (all required):

  1. Victim is logged in to bugcrowd.staging.my.rubrik-lab.com in the same browser.
  2. Victim has the CREATE_CROSS_ACCOUNT_PAIR privilege + replication capability (otherwise the page renders NOT_PERMITTED / UNAUTHORIZED and posts a null payload).
  3. Victim clicks Connect on the confirmation card (it will display your serviceConsumerOrgUrl).
  4. This page must be served over HTTPS from the exact host you put in serviceConsumerOrgUrl (the target origin is https://<that host>). It will NOT fire from file:// or http://.
